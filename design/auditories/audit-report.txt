=====================================================================
2. BUGS & FRAGILITY
=====================================================================

- No 404 catch-all route. App.jsx:67-77 has no <Route path="*">. Any
  unknown URL renders the Nav over a blank page. Add a NotFound page
  (the .profile-not-found styles already exist).
- No scroll restoration. Nothing resets scroll on navigation, and React
  Router doesn't do it by default. Clicking a footer link from the bottom
  of the home page lands you at the bottom of the next page. Add a
  ScrollToTop component on location.pathname in main.jsx/App.jsx.
- Probable production 404s on deep links. There's no vercel.json with an
  SPA rewrite. Unless the Vercel project preset adds the fallback,
  loading arrelat.cat/productors/ca-liula directly (or refreshing)
  returns 404. Verify in production; if broken, add a rewrite of /(.*)
  to /index.html.
- FilterBar controlled-value bug. FilterBar.jsx:6 sets the categoria
  select's value to "comarcaFilter || filters.categoria" — when a comarca
  is picked on the map, a comarca name becomes the value of the category
  select, matching no option (renders blank/first option). Both selects
  should keep their own values and only be disabled.
- Contact form silently eats input. Contacte.jsx:40 sets noValidate while
  relying on required, and there is no JS validation — an empty or
  complete submit just wipes all fields (line 28) with zero feedback.
  Remove noValidate and add a sent-confirmation state (the Professional
  page already has this pattern).
- Unguarded reportatge fields. ProducerReportage.jsx calls r.cos.map
  (96), r.citacio.text (108), r.cosFinal.map (115), r.videos.map (152)
  with no guards. Any future producer whose reportatge lacks one of these
  crashes the whole page. Add optional-chaining guards or (better) a
  dev-time shape check on productors.js.
- Duplicate comarca in Professional list. Professional.jsx:5-15 contains
  both "Aran" (line 7) and "Val d'Aran" (line 13) — same comarca twice in
  both selects.
- Catalan article bug in results count. Professional.jsx:296 renders
  "al ${comarca}" — correct for "al Berguedà" but wrong for
  "a l'Alt Empordà", "a Osona". Needs a small article helper or reworded
  copy ("reparteixen a: {comarca}").
- href="#" with target="_blank" on social links in Footer.jsx:37,41 and
  Contacte.jsx:80,84, and event links url:'#' in agenda.js:8,16 — open
  blank tabs. Point to real URLs or drop target.
- Fragile URL building. ProducerProfile.jsx:234 builds
  "https://${contacte.web}" — breaks the day data includes a protocol.
  Normalize in data or strip protocol before prefixing.
- GeoJSON property guessing. MapaCatalunya.jsx:101 tries four property
  names for the comarca name. You own
  public/data/catalunya-comarques.json — normalize the property once in
  the file and read one key. Also: if the GeoJSON fetch fails, the map
  silently renders empty — no loading or error state.

=====================================================================
4. RESPONSIVE QUALITY
=====================================================================

Overall the CSS is genuinely mobile-first and most grids collapse
sensibly (dir-grid at 900/540, entrevistes at 768, pro-cards wrap at 560,
infobar 2-col at 640). The real risks:

- The map at 375px is the weakest point. The 680x500 viewBox scales to
  ~340px wide, making small comarques nearly unclickable and the
  6px-radius markers (MapaCatalunya.jsx:136) far below the 44px
  touch-target guideline. Tooltips are hover-only, so touch users get
  comarca names only by selecting. Consider a mobile fallback (comarca
  <select> above the map, which FilterBar already almost provides) and
  bigger marker hit areas (transparent larger circle).
- Fixed-height heroes: .report-hero 320px (2788) and .profile-hero 280px
  (2398) — a two-line italic Playfair title at 375px plus the pill gets
  tight; a longer future title will clip. Prefer min-height + padding.
- Profile infobar mobile alignment:
  .profile-infobar__item:first-child { padding-left: 0 } (2479) was
  written for the 4-column layout; in the 2-column mobile grid (2498)
  item 3 starts a row with 1rem padding while item 1 has none — visible
  misalignment.
- Newsletter stacked form at 480px (484-493): the input keeps
  border-bottom:none when stacked above the button, so it appears
  open-ended against the dark background. Restore the bottom border
  inside that media query.
- Pro topbar at 375px (Professional.jsx:224-238): wordmark + badge +
  "Botiga verificada" pill share one 44px row; it fits, but barely —
  worth a real-device check.

=====================================================================
5. PERFORMANCE
=====================================================================

- Fonts are the biggest first-paint cost. index.css:5 loads Google Fonts
  via CSS @import — the worst-case chain (HTML -> CSS -> fonts CSS ->
  font files), render-blocking. Move to <link rel="preconnect"> +
  <link rel="stylesheet"> in index.html, or better, self-host the two
  families with font-display: swap.
- 1.1MB GeoJSON (public/data/catalunya-comarques.json) is fetched at
  runtime on the home page and the directory. Comarca boundaries at this
  rendering size need a fraction of that precision — run it through
  mapshaper (~10-15% simplification survives visually intact) and/or
  convert to TopoJSON; realistic target is 100-200KB.
- 410KB JS bundle, no code splitting. react-simple-maps + its d3
  dependencies ship to every route via the static imports in App.jsx.
  React.lazy on the route components (or at least on MapaCatalunya) would
  cut the initial bundle substantially for
  reportage/professional/contact visitors.
- Map hover re-renders: every mousemove/hover updates state and
  re-renders all 42 Geography elements, calling normalize() several times
  per geography per render (MapaCatalunya.jsx:101-104). Precompute each
  geography's normalized name once (keyed by geo.rsmKey) or memoize.
  Noticeable on low-end devices.
- Plausible is deferred — fine. No real images yet, so LCP is currently
  text on gradient — fine.

=====================================================================
6. SEO & METADATA
=====================================================================

- No per-page titles or descriptions — the most important SEO gap. Every
  route shares "Arrela't — Sector primari català". react-helmet-async is
  already installed and unused; wire it up (or a tiny useDocumentTitle
  hook). Reportage pages especially deserve title/description/OG from
  productor.reportatge.
- theme-color #177245 at index.html:8 — stale green, as noted.
- OG/Twitter incomplete: twitter:card summary_large_image with no
  og:image/twitter:image at all, and no og:url/canonical. Add a branded
  fallback image (1200x630) even before real photos exist.
- No sitemap.xml, no robots.txt. Both are trivial for ~10 static routes.
- rss.xml actively harmful — advertised in <head> and pointing crawlers
  to dead /diari/ and /newsletter/ URLs. Remove or regenerate.
- Client-only rendering: producers and reportages exist only after JS
  executes. Google copes; other crawlers and link-preview bots don't.
  Prerendering the static routes at build time is the structural fix.
- Semantics are decent: lang="ca" OK, one h1 per page OK,
  nav/footer/article used. Weak spot: profile-page sections use
  <span class="profile-label"> instead of real h2s
  (ProducerProfile.jsx:178,187,203), so the document outline under the
  h1 is flat.

=====================================================================
7. ACCESSIBILITY
=====================================================================

- The map is invisible to keyboard and screen-reader users. Geography
  elements have onClick but no tabIndex/role/onKeyDown, and
  outline:'none' (MapaCatalunya.jsx:121) kills any focus indicator;
  markers are plain <circle>s. Tooltips are aria-hidden. Since the
  directory grid + FilterBar duplicate the map's function, the pragmatic
  fix is: mark the map decorative-but-enhanced (aria-hidden on the SVG,
  ensure the select-based filtering is complete), or make markers
  focusable with role="button" and Enter/Space handlers.
- The Professional contact modal doesn't manage focus
  (Professional.jsx:56-149): focus is not moved into the dialog, not
  trapped, and not returned on close; role="dialog" sits on the backdrop
  instead of the panel. Escape and backdrop-click do work. Tab currently
  walks the page behind the modal.
- Systematic contrast failures with --ink-faint (#8a7a64) on paper —
  ratio ~3.6:1, below AA for the small text it's used on:
  .mapa-card__helper (13px), .ultimes-card__data, .entrevistes__card-data,
  .pro-results__count, form placeholders. Darkening --ink-faint to
  ~#75664f fixes all at once. Also failing: .footer__bottom p at
  rgba(paper, 0.4) (~3.4:1, index.css:566) and .pro-teaser__label at
  rgba(paper, 0.65) on terracotta (~2:1, index.css:2243).
- No prefers-reduced-motion guard for scroll-behavior:smooth
  (index.css:38), the .fade-in transforms, and card hover translations.
  One media query at the end of the stylesheet covers it.
- Good points worth keeping: hamburger has aria-expanded + dynamic label,
  form labels are real <label htmlFor> or sr-only, decorative SVGs
  consistently aria-hidden, footer nav has aria-label.

(b) Structural improvements — by value
--------------------------------------
 1. Per-page SEO — wire react-helmet-async for titles/descriptions/OG on
    all routes, add an OG fallback image, sitemap.xml, robots.txt; then
    evaluate build-time prerendering of the static + reportage routes.
    Content-first project; this is where the value is.
 2. Map performance and access: simplify the GeoJSON to ~150KB, lazy-load
    MapaCatalunya (and ideally each route) with React.lazy, memoize
    normalized comarca names, add loading/error states, and a
    mobile/keyboard-accessible alternative (comarca select).
 3. CSS cleanup pass: delete the ~500 lines of orphaned styles, unify the
    container/centering system, introduce --radius tokens, consider
    splitting index.css (3,244 lines) into per-page files.
 4. Shared-code extraction: icons.jsx module, useFadeIn everywhere, date
    utility with ISO dataVisita in the data model, plus a dev-time shape
    check on productors.js so a missing reportatge field fails loudly
    instead of crashing a page in production.
 5. Wire the forms (newsletter, contact, professional access/contact) to
    a real backend — Formspree/Basin for forms, Buttondown/Mailchimp for
    the newsletter. Until then, at minimum make every fake submit show
    the confirmation state so nothing silently swallows input.
 6. Modal & focus management: a small useDialog (focus trap, restore,
    Escape) used by the Professional modal and any future ones.

=====================================================================
BOTTOM LINE
=====================================================================
The architecture is sound for the site's size — static data, plain CSS,
small components. The debt is almost entirely residue from redesigns
(dead pages, orphaned CSS, a broken RSS pipeline, the old green) plus
three user-facing gaps: no scroll restoration, no 404/deep-link
handling, and no per-page SEO. The quick-wins list alone would fix most
of what a visitor or crawler would actually notice.
